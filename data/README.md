# Data layer

All platform features render from the JSON files in this folder. They are the
single source of truth: the home matrix, hub pages, search, breadcrumbs,
cross-link chips and prev/next navigation all read the same rows.

- `tactics.json` — the 15 Enterprise tactics in ATT&CK order (the current
  Stealth / Defense Impairment model). Never changes without a data migration.
- `techniques.json` — one row per technique: `id`, `name`, `tactic`,
  `platforms`, `summary` (max 2 neutral sentences), `status`
  (`implemented` | `planned`), `updated` (ISO date). **Only implemented rows
  carry a `page`**; implemented rows may also carry `used_by` (actor IDs),
  `mitigated_by` (mitigation IDs) and `sigma` (rule file paths). Planned rows
  have no page and therefore produce no dead links.
- `actors.json` — `id`, `name`, `aliases`, `summary`, `status`, `uses`
  (technique IDs), and an optional `page` for an implemented dossier. `uses`
  is the reciprocal of a technique's `used_by`.
- `mitigations.json` — `id`, `name`, `type`, `summary`, `status`,
  `mitigates` (technique IDs). `mitigates` is the reciprocal of a technique's
  `mitigated_by`.
- `campaigns.json` — `id`, `name`, `year`, `summary`, `status`,
  `techniques` (technique IDs).
- `sigma-index.json` — GENERATED by `scripts/build_sigma_index.py` and by CI.
  Never hand-edit it; the next run overwrites your edit.

## Adding a technique page

1. Write the guide and place it under `techniques/`. Use a lowercase,
   hyphenated folder for the technique family and a numeric subpage when the
   technique has sub-techniques, e.g.
   `techniques/T1566-phishing/001-spearphishing-attachment.html`.
2. In `techniques.json`, find the row and set:
   - `"status": "implemented"`
   - `"page": "techniques/..."` — **exact casing**, forward slashes, no leading slash
   - `"updated": "YYYY-MM-DD"`
   - `"sigma": ["sigma/rules/....yml"]` for every rule that detects it.
3. Remove the row's placeholder `page` from planned state if one exists. Do
   not create an empty HTML file for a planned technique; the matrix, hubs and
   search render planned rows without a page.
4. Copy the platform integration block from `techniques/_template.html` into
   the new page (header, stylesheet and `platform.js`). The page must contain
   `data-technique="TXXXX.XXX"`, a meta description and a canonical link.
5. Run the strict gates:

   ```powershell
   py scripts/validate_data.py
   py scripts/check_links.py
   py scripts/check_site.py
   ```

   All three must exit 0. The validator checks **case-exact** paths on
   Windows, so a path that works locally but 404s on the Linux Pages server
   fails before it is committed.

## Verification note

The relationship arrays were populated from the public ATT&CK STIX bundle
(`mitre-attack/attack-stix-data`); the validator warns when a relationship
exists in only one direction. Re-run the import when ATT&CK publishes a new
release and review the diff.

## JSON hygiene

No trailing commas, no comments, UTF-8 without BOM, one trailing newline.
Run the validator after every edit.
