T1590.004

Network Topology

Network topology is the map of a network: which address blocks and subnets exist, and where the gateways, VPN doors, and public services sit. Attackers draw this map from the outside, before they touch any door. This guide shows how they do it and how defenders catch the drawing.

01

Overview: What Is This Technique?

MITRE ATT&CK is a free, public knowledge base of attacker behavior. Every behavior gets an ID, like a street address for an attack step. Defenders use these IDs to name what happened, to plan defenses, and to write detection rules. This page belongs to the T1590 family, called Gather Victim Network Information. The whole family sits in the Reconnaissance tactic. That is the stage where the attacker learns about the target and does not break in yet.

Sub-technique T1590.004 is called Network Topology. A topology is the physical and logical arrangement of a network. It covers the external-facing side and the internal side: which subnets and IP ranges exist, how they connect, and where the gateways and routers sit. Attackers collect this from public records and from scanning. Some also read the victim's own websites, because job adverts and support pages often describe the network in plain words. Others trick people with fake surveys or messages; ATT&CK calls that Phishing for Information. The finished map tells the attacker which doors exist. Very often they pick a VPN gateway or another remote service, because one valid login replaces a whole phishing chain. ATT&CK links this step to External Remote Services, a very common way in.

In this guide you will learn both sides of the technique. An animated simulation shows how an outsider draws the map, step by step, and what a defender sees at the same moment. The red team section shows the tools and the order of work. The blue team section shows the traces this work leaves behind. The detection deep dive gives you regulation mapping, threat intelligence, ranked threats, real log examples, five Sigma rules, and matching Splunk SPL queries.

Why should you care?

  • The map comes first. Serious attackers draw it before they choose any entry point, especially VPN gateways and edge devices.
  • Mapping leaves echoes. Traceroute answers, scan denies, and portal requests all land in your logs. They are your earliest warnings.
  • Your footprint is public. Scan databases list your open services and versions, whether you know it or not.
  • The map feeds the breach. A good map often ends in quiet access through a remote service, so early detection buys real time.
  • Cheap rules win. Simple log rules for mapping fire days or weeks before any intrusion attempt.
How to read this guide

Watch the simulation first. It shows the whole story in about one minute. Then read the red team and blue team sections to understand both sides. Keep the detection deep dive as your work reference. It has logs, five Sigma rules, and SPL queries that you can copy, adjust, and test in your own lab.

03

Red Team View: How Attackers Do It

This section explains how professional red teams and real attackers map a network from the outside. It is for learning and defense. Only test systems you own, or systems you have written permission to test.

When: before any door is chosen

Topology mapping happens in the Reconnaissance stage, before the attacker tries any login. A red team draws the map at the start of every engagement, and repeats it when the network changes. Real groups often collect the map over weeks while doing nothing else. It is quiet, and quiet is the point. The finished map also ages well: a subnet drawn today is still useful in three months.

How: passive first, then careful probes

Passive work reads public data and never touches the target. BGP looking glasses (public servers that show internet routing data) reveal which address blocks a company announces. WHOIS (the public registry for IP and domain owners) shows who holds a range and how big it is. Traceroute shows the router path to each public address, hop by hop. Scan databases such as Shodan and Censys show what earlier public scans already found: open ports, banners, and sometimes whole VPN portals.

Active work sends packets, so it turns slow and small. A careful scan uses a low packet rate and a short port list. Professionals probe the likely doors only: VPN on 443, 500, and 4500, mail on 25, and the published web services. Slow, small, and patient beats fast and loud.

The typical order of work

  1. Collect address blocks and owners from WHOIS and BGP data. This builds on the domain and DNS work from T1590.001 and T1590.002.
  2. Confirm the paths with traceroute or mtr from a few vantage points, so one blocked path does not hide the real hop count.
  3. Check scan databases for known open services, versions, and exposed admin pages.
  4. Run a low-rate ping sweep with nmap -sn to confirm which addresses answer.
  5. Probe the likely doors only: VPN, mail, and the published web services.
  6. Write the map down and pick the quietest path. The next step is usually T1595 Active Scanning or a login attack on the remote service.

Where: from the outside, with no access

All of this runs from a normal internet connection: a rented cloud server, a VPN exit, or a home line. The attacker needs no account and no malware. That is why ATT&CK marks the platform PRE. The only thing the attacker shares with the target is traffic: packets out, answers back.

Why: what the finished map gives

  • Entry points. VPN portals and edge devices are the classic quiet path, because one valid login replaces a phishing chain.
  • Layout. Knowing that web, mail, and VPN sit apart tells the attacker which alarms to expect and which failures are survivable.
  • Quiet paths. The map shows which ranges answer politely and which answer loudly, so the attacker avoids noisy mistakes.
  • Routing insight. ASN and prefix data also prepare interception attempts and Adversary-in-the-Middle setups.

What is needed

The bar is low, and that is the problem. Public routing data is free, scan databases are cheap, and the tools below are standard. The only real cost is patience, because a low-and-slow sweep takes days of small steps.

Ethics and law

Only scan your own lab, or targets you have written permission to test. Scanning other people's networks is a crime in many countries, even when no damage is done. When in doubt, do not send the packet.

04

Blue Team View: How Defenders See It

Now flip the view. This section shows what defenders can see while an attacker maps the network, where the traces live, and why this early stage is worth watching closely.

The artifacts: what mapping leaves behind

Passive reading of WHOIS and routing data leaves no trace on your systems, because the attacker never touched you. Everything else does leave a trace. Each traceroute probe makes an edge router send an ICMP time-exceeded message back. Each scan packet that hits a closed door makes the firewall log a deny. Each visit to the VPN login page lands in the web server log.

ArtifactWhere it appearsWhat it tells you
ICMP time-exceeded messages sent from your edgeRouter syslog, firewall logs, ZeekSomeone is walking the path to your edge, hop by hop.
Deny storms: one source, many doorsFirewall logs, SIEMA horizontal or vertical scan is in progress.
Many requests to /remote/login or admin pathsWeb server logsThe attacker found the portal and is profiling it.
Short sessions to VPN ports (443, 500, 4500) with no loginFirewall logs, VPN logs, NetFlowThe attacker is testing the door before trying credentials.
Your assets listed in public scan databasesShodan, CensysYou can see exactly what the world already knows about you.

What mapping does NOT leave

No malware, no failed logins, and no account lockouts at this stage. Mapping uses open doors and public data, so identity logs stay quiet. That is why network logs and web logs matter more here than authentication logs.

Where to look

The traces live at the network boundary. Firewall logs hold the deny storms. Edge router logs hold the time-exceeded messages that traceroute causes. Zeek and NetFlow show the shape of a scan even when packets are rare. Web server logs show portal probing. Passive DNS (a public history of which names pointed at which addresses) adds context about your own edge names. All of it belongs in one SIEM, where a small set of rules turns raw echoes into a clear signal.

Why early visibility matters

The map comes before the intrusion. Public reporting on patient actors shows weeks or months of mapping before the first login. If you know you are being mapped, you have bought time. Use it to patch the edge devices, rotate remote-access credentials, and review your exposure list. That warning is cheap. A few simple rules over firewall, router, and web logs give you notice days or weeks ahead.

How it fits the attack chain

Topology mapping sits before Initial Access. It feeds T1595 Active Scanning, which sharpens the map with more probes. The finished map often ends at T1133 External Remote Services: a quiet login through a VPN or remote portal. After access, the same work repeats inside with T1046 Network Service Discovery and T1018 Remote System Discovery. A detection here is the front door alert for a whole chain.

Defender mindset

You cannot hide a public network. The addresses are public data, and someone will always scan them. But you can make the map wrong, slow, and noisy. Rate-limit the answers, deny quietly, log everything, and add decoy boxes that waste attacker time. A wrong map sends the attacker down a path you control.

5.1Regulation Mapping

Mapping activity itself breaks no regulation. But being mapped usually comes before a breach, and most security laws expect you to monitor, detect, and respond. The table below lists the controls that ask for exactly this kind of boundary monitoring. Auditors often ask for proof that deny logs and router messages are really collected and reviewed. 5.4Logs and Patterns

Each mapping behavior writes its own lines into your logs. This subsection shows one realistic example per source, plus the pattern to look for. All values are fake documentation values: the attacker sits at 203.0.113.50, and the victim network is 192.0.2.0/24.

pfSense firewall denies (threats 2 and 3)

Use your firewall log for horizontal sweeps and vertical profiles. The SIEM parses the raw filterlog lines into fields like action, src_ip, dest_ip, and dest_port.

pfsense filterlog - block lines (fake data)
Sep 29 10:22:31 fw-edge filterlog[5213]: 65,,,1000000103,em0,match,block,in,4,0x0,,64,54213,none,6,tcp,40,203.0.113.50,192.0.2.10,51234,443,S
Sep 29 10:22:32 fw-edge filterlog[5213]: 65,,,1000000103,em0,match,block,in,4,0x0,,64,54214,none,6,tcp,40,203.0.113.50,192.0.2.15,51235,443,S
Sep 29 10:22:33 fw-edge filterlog[5213]: 65,,,1000000103,em0,match,block,in,4,0x0,,64,54215,none,6,tcp,40,203.0.113.50,192.0.2.15,51236,3389,S

What to look for:

  • The same src_ip with many different dest_ip values means a horizontal sweep across the block.
  • The same source and destination with climbing dest_port values means a vertical profile of that host.
  • Counts per 5 minutes matter more than single lines. One deny is noise; thirty is a scan.

Zeek connection log: traceroute probes (threat 4)

Use Zeek conn.log to see the shape of a traceroute sweep. The classic traceroute sends UDP probes to ports starting at 33434.

zeek conn.log - udp probes to traceroute ports (fake data)
#fields ts uid id.orig_h id.orig_p id.resp_h id.resp_p proto service duration orig_bytes resp_bytes conn_state
1727612551.044221    CeXk9a2Pq3fZ    203.0.113.50    44871    192.0.2.1    33434    udp    -    0.002    0    0    OTH
1727612551.512004    CeXk9a2Pq3gQ    203.0.113.50    44872    192.0.2.1    33435    udp    -    0.002    0    0    OTH

What to look for:

  • One id.orig_h probing ports 33434 and above in rising order is the classic traceroute pattern.
  • The edge answers each probe with an ICMP time-exceeded message, which shows up in router logs.
  • Short, empty connections (conn_state OTH, zero bytes) repeated in a burst mean path mapping.

Edge router syslog: ICMP time-exceeded (threat 4, second view)

The router that drops a traceroute probe writes a message of its own. This log is small, so keep it and ship it.

edge router syslog - traceroute echoes (fake data)
Sep 29 10:15:02 edge-r1 41201: Sep 29 10:15:02.104: %IP-4-TIMEEXC: Sending ICMP time exceeded to 203.0.113.50, reason: ttl=1, proto=17
Sep 29 10:15:03 edge-r1 41202: Sep 29 10:15:03.011: %IP-4-TIMEEXC: Sending ICMP time exceeded to 203.0.113.50, reason: ttl=2, proto=17

What to look for:

  • Time-exceeded messages aimed at one external address, repeating over minutes.
  • Rising TTL values in one burst mean the tracer is moving inward, hop by hop.
  • Correlate the source with later portal probes or denies from the same address.

Apache web server log: portal probing (threat 1)

Use the web server log of your VPN portal and other public services. The combined format shows the source address, the path, and the result.

apache combined access log - portal probing (fake data)
203.0.113.50 - - [29/Sep/2026:10:22:31 +0000] "GET /remote/login HTTP/1.1" 200 5123 "-" "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"

What to look for:

  • Many portal and admin paths from one source within minutes.
  • A mix of 200 and 403/404 answers shows path guessing without a real session.
  • Check the user agent: scripts reuse one string across all requests.

After access, the attacker maps the inside with built-in tools. Sysmon EventCode 1 records every process launch. Remember: this stage is post-compromise mapping, and MITRE tracks it as Discovery.

  • Admins use the same tools, so allow known admin workstations and review the rest.
Threats 6 to 8

Routing hijack prep, forgotten ranges, and scan-database exposure leave no logs on your own systems. Watch public route monitors for your prefixes and check scan databases for your assets on a schedule. That review sits outside the SIEM, but it belongs to the same quarterly routine.

5.5Sigma Rules (Detection as Code)

Sigma is a plain-text rule format that describes a detection once and converts into queries for many SIEM products. The five rules below cover the top five threats from section 5.3. Rules R1 to R4 watch the border of the network. Rule R5 watches the related post-compromise mapping stage inside Windows, which MITRE tracks as Discovery, not as Reconnaissance. Keep the rules as code in version control, and tune every threshold against your own noise floor.

high R1 · Horizontal sweep across the external range

Catches one external source denied on more than 25 different destination IPs at the boundary within five minutes; level high; main false positive: an approved external vulnerability scanner.

Real-World Scenario: Quiet maps of critical pipes — Volt Typhoon

This scenario is based on public reporting: CISA advisory AA24-038A on PRC state-sponsored actors, tracked as Volt Typhoon. The organization in the story is invented and the dates are illustrative. The pattern follows the advisory.

Background

Volt Typhoon is the name public reporting uses for a PRC state-sponsored group. CISA advisory AA24-038A, published in February 2024, describes how this group targets the communications, energy, and water sectors in the United States. The goal is not quick profit. The actors want quiet, long-term access inside critical infrastructure.

Their method starts with the topic of this guide. They map the victim's network from the outside for a long time. They look for edge devices, VPN portals, and the general layout. Only then do they use valid accounts. After access they live off the land, which means they use normal admin tools instead of malware. The utility below is a realistic composite built on that advisory, focused on the mapping phase.

The attack chain

Early 2023 (illustrative)

The quiet map begins

The actors read public routing and registry data about the utility. They run traceroute from a few vantage points and study public scan databases. Almost nothing touches the utility, so almost nothing appears in the logs.

Months 1 to 3

The edge comes into focus

Slow, low-rate probes confirm the edge router and the VPN portal. The firewall logs a few denies per hour. Two people run IT, and nobody has a rule for this pattern.

Month 4

The old door is chosen

Public data and quiet probes point at an end-of-life edge device with an old firmware version. The map says this is the quietest path in. The actors now know the doors without ever forcing one.

Month 5

Valid accounts, no malware

With credentials obtained quietly, the actors sign into the VPN. The map they drew guides them, so they rarely scan inside. They use normal admin tools on Windows.

Months 5 to 10

Hands on keyboards, tools built in

The actors keep access, create extra valid accounts, and move carefully. Living off the land keeps antivirus quiet. The outside map now grows on the inside, one admin command at a time.

Month 11

Federal partners raise the flag

There is no single hero alert. Federal partners share indicators with the sector, and the utility starts a joint hunt over its old logs. The mapping echoes are months old by now.

Month 11 to 12

The hunt finds the echoes

Analysts compare normal-week baselines with the router and edge logs. The slow deny pattern and the portal requests without logins stand out. Passive DNS records add context about names that once pointed at the edge devices.

Month 12

Response and rebuild

The utility isolates the edge devices, rotates every credential, and rebuilds devices where firmware tampering was possible. New logging rules go live, and the team keeps watching.

How it was detected

The detection was a hunt, not a single alert. The network team pulled edge router logs, firewall denies, and VPN session records into one place. They compared each source with a baseline from a normal week. Three weak signals lined up: time-exceeded echoes toward one address, a steady deny pattern from the same address, and portal requests without any login. A passive DNS lookup added context about names that pointed at the edge devices. No single line was loud, but the pattern was clear once the logs were joined.

Containment

  • Edge devices were isolated from the rest of the network, because their firmware could no longer be trusted.
  • The actor's addresses and accounts were blocked at the boundary.
  • Every VPN, local admin, and service credential was rotated, and all sessions were forced to log in again.

Recovery

  • Edge devices with suspected tampering were rebuilt with clean firmware and known-good configs.
  • Logging was shipped to the SIEM, and the rules from section 5.5 went live.
  • The utility joined its sector ISAC, so the next advisory reaches someone who will read it.

Impact and consequences

No water service was disrupted in this story, and that is exactly the point. The danger of this attack style is pre-positioning: an actor who is ready inside a water network is a national security problem, even if nothing happens for months. For the utility, the costs were downtime during the rebuild, outside help fees, and weeks of extra work for a two-person team. For the towns, the cost was trust.

Lessons learned

  • Know your edge. A live list of public addresses, services, and devices is the base of everything.
  • Mapping is visible. The deny pattern and the time-exceeded echoes were there for months.
  • Baselines matter. Without a normal-week baseline, slow and quiet patterns hide in plain sight.
  • Hunt on purpose. Waiting for an alert is not enough; go and look for the quiet patterns.
  • Old firmware is a map marker. End-of-life devices attract the first arrows.
  • Share intel. The advisory reached the utility through partners, and it made the hunt possible.

Team response and communication

  • The two-person IT team owned the timeline and kept one written record of every action with times.
  • An external incident response firm handled the edge rebuild and the credential rotation.
  • Management told the board and the regulator the facts only: what was seen, what was done, what comes next.
  • One spokesperson talked to towns and press, so the technical team could keep working without interruption.

Public sources

  • CISA and FBI, advisory AA24-038A: PRC State-Sponsored Actors Compromise and Maintain Persistent Access to U.S. Critical Infrastructure, February 2024. cisa.gov

Mitigation and Defense

No single control stops network mapping, because the public part of your network cannot be hidden. The goal is a stack: reduce what is visible, slow what must be visible, and log everything. Layer several measures below, and the map the attacker draws becomes wrong, slow, and expensive.

Enterprise defenses

  • Inventory the edge. Keep a live list of public addresses, open ports, and certificates, and close what has no owner.
  • Patch the edge first. Update or replace end-of-life devices; old firmware is the first thing mapping finds.
  • Protect the doors. Require MFA and conditional access on the VPN and admin portals.
  • Tame ICMP. Scope and rate-limit ICMP at the edge, so traceroute gets few answers.
  • Ship the echoes. Send firewall denies, router messages, and web logs to the SIEM, and deploy the rules from section 5.5.
  • Segment. Split DMZ, office, and core networks, so a correct external map gains little inside.
  • Add decoys. Honeypot subnets and canary routers make the map wrong and alert on any touch.
  • Keep routing honest. Use RPKI where possible, monitor your prefixes, and keep registry records correct.
  • Correlate over time. Keep recon alerts at least 90 days and join them with later login attempts.

Home & small business defenses

  • Turn off WAN ping on your router, so your address answers fewer questions from the internet.
  • Update the router firmware regularly; scan databases list old versions for everyone to see.
  • Disable UPnP, because it opens ports by itself and grows your public footprint.
  • Put smart home devices on a guest network, so one scanned device cannot see your laptops and files.
  • Close what you do not use. Turn off remote administration and any port forwarding you no longer need.
  • Small business extra: use MFA on every remote access tool and change all default passwords.

Glossary of Key Terms

Every technical term used in this guide, explained in simple words.

Network topology
The map of a network: what is connected to what, which subnets exist, and how traffic flows between them.
Subnet
A smaller section of a network, for example one office floor or one server zone, with its own address range.
IP range / CIDR
A block of IP addresses written with a suffix like /24, which means 256 addresses in one block.
DMZ
A buffer zone of a network where public services like web and mail live, separated from the internal network.
Gateway
A device or service that connects one network to another and forwards traffic between them.
Router
A device that sends packets between networks and decides the path each packet takes.
Traceroute
A tool that shows the router path to a target by making each router on the way answer once.
TTL
Time to live: a counter in every packet that drops by one at each router, so packets cannot loop forever.
ICMP time-exceeded message
The answer a router sends when a packet's TTL reaches zero. Traceroute collects these answers to draw the path.
BGP
Border Gateway Protocol: the routing system of the internet, where networks announce which addresses they own.
ASN
Autonomous System Number: the ID of one organization's network in the BGP routing system.
WHOIS
A public directory that lists who owns an IP range or a domain, and how big the range is.
NetFlow
A summary of traffic between hosts: who talked to whom, on which ports, and how much, without the content.
Zeek
A network sensor that logs connections and protocols in detail, so analysts can search them later.
VPN portal
The login page of a remote access service. It is a favorite target because one valid login opens the network.
Living off the land
Using normal admin tools already on a system instead of malware, so defenses see nothing new.
Passive DNS
A public history of which domain names pointed at which addresses over time.
